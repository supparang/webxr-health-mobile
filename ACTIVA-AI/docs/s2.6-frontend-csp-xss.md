# ACTIVA-AI S2.6 — Frontend CSP, XSS & HTML Security

**Change:** integrated-security branch descendant of S2.5, Draft-only. Never merge
or deploy to Production without an independent review and real browser QA.

## Scope / current implementation

ACTIVA-AI serves pages from both a Node backend and static GitHub Pages.
Setting only a Node response header would **not** protect GitHub Pages.
This iteration installs an **enforced HTML-meta CSP** in all four documents
(`index.html`, `Login.html`, `guest.html`, `blind-review.html`), and an
equivalent **HTTP CSP header** on all HTML responses served by the backend.

- `script-src`: `'self'` plus the exact reviewed **versioned QR libraries**
  on cdnjs/unpkg and the official Google Identity Services client URL.
  It does **not** include `'unsafe-inline'` or `'unsafe-eval'`.
- `script-src-attr 'none'`: blocks inline HTML event-handler attributes
  such as an injected `onerror=` or `onclick=`.
- `object-src 'none'` and `base-uri 'self'`: disallow embedded plugins and
  attacker-controlled document base URLs.
- `frame-src https://accounts.google.com/gsi/`: Google Identity iframe,
  and `style-src` allows Google's official GIS stylesheet.
- `connect-src 'self' https: http://localhost:* http://127.0.0.1:*`:
  retained cross-origin HTTPS support because the Pilot API destination is
  selected and validated dynamically at runtime. **This is broad and
  must be narrowed to approved API origins at institutional deployment.**
- `style-src 'unsafe-inline'`: **CSS only**, required for existing legacy
  inline style attributes. Removing it needs a separate refactor.
- `img-src`, `media-src`, and `worker-src` preserve QR graphics and camera
  scanning needs, pending manual browser acceptance.
- `frame-ancestors 'none'` is delivered in the **Node CSP header** (alongside
  existing `X-Frame-Options: DENY`), but is **not** supported by HTML meta CSP.
  If GitHub Pages cannot supply equivalent hosting response headers, move
  sensitive UI to a controlled origin or add suitable edge response headers.

Google Identity Services documents `https://accounts.google.com/gsi/` under
`connect-src` and `frame-src`, and `/gsi/client` and `/gsi/style` under
`script-src` / `style-src`, respectively:
https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid

## Removal of inline JS and XSS defense in depth

- The executable `<script>location.replace(...)</script>` in `Login.html`
  was moved to the local file `login-redirect.js`, which is allowlisted for
  backend public static serving and included in both Docker targets.
- HTML-escape the session role, page title and API-created fixture count before
  inserting those values into existing dynamic HTML templates in `app.js`.
- Existing template-heavy `app.js` **still uses innerHTML extensively**; the
  CSP layer does not establish all interpolations are safe. A full DOM sink
  and attribute-context audit plus targeted migration to `textContent` /
  safe DOM construction remains a prerequisite for Production acceptance.
- External CDN QR libraries are version pinned but **not yet protected by
  checked Subresource Integrity hashes or vendored audited copies**. Treat
  supply-chain integrity review as an open risk.

## CI and functional verification

- `node tests/frontend-csp.mjs`: checks policy equality between all four HTML
  pages and backend header; no inline JS/event attributes; trusted script
  locations; Login redirect file exists; reject `eval` and `document.write`
  introduction; check representative escaped dynamic sinks.
- `tests/smoke.mjs`: verifies real HTTP CSP response headers for `/`,
  `/index.html`, `/Login.html`, `/guest.html`, `/blind-review.html`,
  `/guest`, and `/blind-review`, and that `login-redirect.js` is accessible.
- Docker build includes `login-redirect.js` in migration and runtime images.
- CI is *not* a browser compatibility test. Before Staging GO manually verify
  Google Workspace and Pilot Gmail sign-in, popup and iframe, dynamic QR
  generation/scanning (camera permission), guest accountless flow, external
  blind-review link, menu interactions, page styling on mobile, and
  separately hosted GitHub Pages.

## Blocking gates

1. Full ACTIVA-AI CI PASS for exact commit.
2. Manual DevTools CSP console inspection and UI acceptance on **Staging**.
3. Check all CSP violation categories; revise narrow allowlists without
   ever adding `'unsafe-inline'` to JavaScript or blanket `https:` under
   `script-src`.
4. Approve and pin specific API domains in `connect-src`, and assess
   hosting-level `frame-ancestors` for static pages.
5. Complete comprehensive XSS/DOM-attribute review, CDN SRI or audited
   vendoring, and authorized penetration assessment.
6. Preserve S2.1–S2.5 authorization, throttling, logging, incident response
   and all research ethics HOLD gates.
