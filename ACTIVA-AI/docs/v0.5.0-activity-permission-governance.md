# ACTIVA-AI V0.5.0 — Activity Permission Governance

## หลักการ
Role ของบุคลากรไม่ควรถูกเปลี่ยนไปมาตามกิจกรรม สิทธิ์การกำหนดกิจกรรมจึงเป็น permission แยกต่างหากและ ADMIN เป็นผู้ grant/revoke

## Permission keys
- CAN_CREATE_ACTIVITY
- CAN_EDIT_OWN_ACTIVITY
- CAN_ASSIGN_CO_ORGANIZER
- CAN_ASSIGN_VERIFIER
- CAN_CLOSE_ACTIVITY
- CAN_MANAGE_ALL_ACTIVITIES

## Governance
ทุกการเพิ่ม ปรับ หรือลดสิทธิ์ต้องระบุเหตุผล และระบบบันทึก:
- ผู้ให้/ถอนสิทธิ์
- ผู้รับสิทธิ์
- permission key
- ช่วงเวลาที่มีผล
- เหตุผล
- timestamp

## Primary Organizer
เมื่อบุคลากรที่มี CAN_CREATE_ACTIVITY สร้างกิจกรรม ระบบตั้งผู้สร้างเป็น Primary Organizer อัตโนมัติ
หาก ADMIN สร้างแทน สามารถเลือก Primary Organizer ได้เฉพาะบุคลากรที่มีสิทธิ์ CAN_CREATE_ACTIVITY

## Transitional note
UserRole เดิมยังคงอยู่เพื่อไม่ทำลาย flow รุ่นก่อน แต่ authorization สำหรับการสร้าง/จัดการกิจกรรมเริ่มย้ายมาใช้ Activity Permission ตั้งแต่ V0.5.0
