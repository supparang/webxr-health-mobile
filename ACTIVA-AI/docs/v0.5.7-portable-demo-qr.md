# ACTIVA-AI V0.5.7 — Portable Demo QR

## ปัญหาที่แก้
Demo Mode เก็บ activity ใน localStorage ของแต่ละอุปกรณ์
เดิม QR มีเพียง activityId + timestamp ดังนั้นเมื่อสร้างกิจกรรมบนเครื่อง A แล้วสแกนด้วยเครื่อง B เครื่อง B หา activityId ไม่พบและแสดงเหมือน QR หมดอายุ แม้หน้าจอ QR ยังเหลือเวลา

## แนวทาง V0.5.7
Demo QR format: ACTIVADEMO1.<base64url-payload>

Payload มีเฉพาะข้อมูลที่จำเป็นต่อการทดสอบ:
- activity id/title/category/location
- activity time และ check-in/check-out windows
- participation mode
- roster employee IDs หรือ department codes
- evidence policy
- issued-at / expiry / nonce

เมื่อเครื่อง B สแกน:
1. decode payload
2. ตรวจ expiry/clock
3. สร้าง activity shadow ใน localStorage ของเครื่อง B
4. ตรวจ check-in window
5. ตรวจ OPEN/ROSTER/GROUP
6. ตรวจ identity
7. ตรวจ duplicate
8. บันทึก check-in ในเครื่อง B

## Security
Portable Demo QR เป็นกลไกสำหรับสาธิตเท่านั้น ไม่ใช่ cryptographic production token
Server Mode ยังคงใช้ signed token ฝั่ง server

## ข้อจำกัดสำคัญ
เพราะ Demo Mode ใช้ localStorage การบันทึก Attendance ยังไม่ sync ข้ามอุปกรณ์
การแชร์ Attendance จริงระหว่าง Participant/Staff/Admin ต้องใช้ shared backend เช่น Server Mode + PostgreSQL
