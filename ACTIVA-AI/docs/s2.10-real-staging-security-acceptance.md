# ACTIVA-AI S2.10 — Real Staging Security Acceptance

**สถานะ: HOLD — ยังไม่มีหลักฐานตรวจรับจาก Staging จริง**

เอกสารนี้ต่อยอดจาก S2.9 PR #144 บนสาขาแยก และยังไม่มีการ Merge
หรือ Deploy เข้าสู่ Production กิจกรรมทุกข้อเกี่ยวกับผู้เข้าร่วมจริง
ต้องรอการอนุญาตด้านจริยธรรมการวิจัยและหน่วยงานตามขั้นตอน Phase 4

## ขอบเขตที่ตรวจด้วยระบบอัตโนมัติได้

ไฟล์ `scripts/verify-staging-security.mjs` ตรวจสภาพแวดล้อม **ที่ทราบ
โดเมน Staging ที่อนุมัติล่วงหน้าอย่างชัดเจน** และยืนยันว่าเป็น Commit
ที่ต้องการทดสอบ ก่อนรายงานผล PASS/HOLD

- ตรวจ Staging `/api/live`, `/api/ready`, `/api/health`
  ด้วยตัวตรวจเดิม `verify-staging.mjs` รวมถึงการยืนยันตัวตน,
  CORS, การป้องกันไฟล์ระบบรั่วไหล, Header พื้นฐาน และการปิด Production GO
- ตรวจให้ sourceCommit ของ 3 จุดตรงกับ SHA ที่กำหนดทั้งหมด
- ตรวจ 5 เส้นทาง HTML ด้วย HTTP 200, Content-Type, CSP Header,
  การป้องกันการฝังเว็บไซต์, การไม่แคชข้อมูล และ CSP Meta
- ตรวจ SRI ในหน้า `index.html` ว่า SHA-384 ของ QR ทั้งสองไลบรารี
  ตรงกับ `tests/browser-asset-integrity.json`
- ใช้เฉพาะ `GET` และ `OPTIONS` พร้อม `credentials: omit`,
  ไม่ส่ง Cookie, Token, Form หรือคำขอแก้ไขข้อมูล
- ปิดการติดตาม Redirect, จำกัดเวลารอ และแสดงเฉพาะ PASS/FAIL เป็นรหัส
  ไม่พิมพ์ Body จาก API ที่อาจมีข้อมูลสำคัญ
- บังคับ exact-approved-origin ของ Staging, HTTPS, โฮสต์ที่แยกจาก Production
  และ SHA แบบ 40 ตัวอักษรก่อนส่งคำขอใด ๆ

## วิธีใช้กับ Staging ที่อนุมัติแล้ว

**ขั้นตอนนี้ยังไม่ได้ดำเนินการกับ Staging จริงใน PR นี้**
และไม่ควรใช้ URL Production แทนเด็ดขาด
ผู้ดูแลควรตรวจว่า URL เป็นระบบทดสอบที่แยกจาก Production มีฐานข้อมูลทดสอบ
และไม่มีบุคลากร/ผู้เข้าร่วมจริง ก่อนอนุมัติให้เรียกใช้งาน

ตั้งค่า Environment Variables ผ่านเครื่องผู้ตรวจหรือ GitHub Staging Environment
ที่ผ่านการอนุมัติเท่านั้น ไม่บันทึกข้อมูลลับในคำสั่งหรือ GitHub Issue:

```bash
export ACTIVA_S210_STAGING_URL="https://<approved-staging-host>"
export ACTIVA_S210_APPROVED_ORIGIN="https://<approved-staging-host>"
export ACTIVA_S210_FRONTEND_ORIGIN="https://<approved-frontend-origin>"
export ACTIVA_S210_EXPECTED_COMMIT="<40-character-deployed-SHA>"
export ACTIVA_S210_READ_ONLY_CONFIRM=true
node scripts/verify-staging-security.mjs
```

การแทนค่าเป็นชื่อโฮสต์ที่ผ่านการอนุมัติจริงต้องดำเนินการโดยผู้ดูแล
ตัวอย่างข้างต้นเป็น placeholder ไม่ใช่ URL ที่ได้รับการยืนยัน

**เกณฑ์ PASS อัตโนมัติ:** ทุก `checks[]` เป็น `passed:true`
และ `automatedChecksPassed:true` เท่านั้น

แม้ PASS ทั้งหมด ผลรายงานยังคงระบุ
`productionGoApproved:false`, `researchEthicsApproved:false`
และ `manualAcceptanceStatus:"NOT_TESTED"` โดยออกแบบไว้
เพื่อป้องกันการสรุปว่าอนุมัติการใช้งานโดยอัตโนมัติ
