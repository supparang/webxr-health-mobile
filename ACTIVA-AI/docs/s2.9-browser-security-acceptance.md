# ACTIVA-AI S2.9 — Browser Security Verification

**Status:** Draft integration validation, not Production or deployed Staging
approval. This PR is stacked on S2.8 PR #143, and earlier S2 security PRs
remain unmerged. All automated tests use disposable, synthetic GitHub CI data.

## Actual headless Chromium tests added

`tests/browser-security-ci.mjs` uses pinned `playwright-core@1.56.1`
and the preinstalled Google Chrome binary on the GitHub-hosted Ubuntu runner.
This is a **real browser** rather than merely parsing HTML or fetching headers,
but not a physical device or the institutional Staging host.

| ID | Test | What counts as PASS |
| --- | --- | --- |
| S29-01 | CSP response headers | 5 HTML routes have CSP and anti-framing directives |
| S29-02 | Main UI rendering | Actual JavaScript executes and `#app` becomes populated |
| S29-03 | QR libraries | Browser loads both version-pinned QR JS files and exposes functions; SRI attrs match approved manifest |
| S29-04 | XSS mitigation | Browser blocks injected inline script and inline `onerror` attribute |
| S29-05 | Login redirect | Legacy Login page redirects via local JS file rather than inline execution |
| S29-06 | Guest fragment hygiene | Fake, unusable Guest token is stripped from URL fragment/history |
| S29-07 | Blind Review fragment hygiene | Fake reviewer token is stripped from URL fragment/history |
| S29-08 | SRI tamper | Browser intercepts QR CDN script with different bytes; SRI rejects execution |
| S29-09 | Mobile viewport | UI renders in Chromium's 390 × 844 touch/mobile emulation without excessive horizontal overflow |

**Evidence:** GitHub Actions run output `S2_9_PASS ...` and downloadable
artifact `activa-s2-9-browser-security-evidence` containing
`test-results/s2-9-browser-security.json`. No raw bearer URLs, personal
data, screenshots, tokens or staff emails are included. The artifact explicitly
states that Google OIDC login, physical camera, real Staging delivery and
operator notifications were *not* tested.

## Safety and operational boundaries

The test **fails closed** if CI/STAGING synthetic guards or the disposable
localhost PostgreSQL URL are absent, if the backend is not localhost:3000,
or if the Chrome executable is not set. It uses fake unusable Guest/Reviewer
tokens, never authentic personnel/participants, and tests external CDN only
to load pinned QR JavaScript needed for SRI verification.

Actual backend CI remains responsible for all existing role/Guest/Blind
Review/QR business-flow tests. Headless browser tests cannot make a real
Google OAuth popup authenticate or activate a phone's physical camera.

## Blockers for Production GO

- All relevant S2.1–S2.8 Draft branches require controlled integration and
  independent code review before any merge. This S2.9 test cannot override
  them.
- Hosted GitHub Pages meta CSP cannot set `frame-ancestors`; verify
  appropriate hosting response headers or migrate sensitive pages.
- `connect-src https:` and inline CSS remain broad. Any CSP changes must
  preserve Google OIDC, QR, camera and Guest/Reviewer functional behavior.
- Obtain results from real Staging on actual desktops/phones; test alert
  delivery and acceptance by humans. Confirm RBAC/directory, incident
  response, privacy, backups, load testing and authorized penetration test.
- Passing an automated CI browser suite does not imply the enterprise system
  is fully secure or approved for use with research participants.
