## 4. Auditable decision tool

- **Review input:** `security/s2.12-review-input.template.json`.
  Truthfully records no deployed release candidate, previous CI evidence
  only, no accepted Staging, manual tests M01–M13 as NOT_TESTED and
  unsigned reviews.
- **Evaluator:** `scripts/assess-production-security.mjs`.
  Reads local JSON only and returns `HOLD` with a list of missing
  category/owner gate codes, or `READY_FOR_HUMAN_DECISION` if *all*
  evidence has been declared complete and current.
- **No auto-GO:** Both outcomes always have
  `productionGoApproved:false`, `mergeApproved:false`,
  `deploymentApproved:false`, and `researchEthicsApproved:false`.
  `READY_FOR_HUMAN_DECISION` is **not** the same as GO.
- **Current evaluation command:**

```sh
cd ACTIVA-AI
node scripts/assess-production-security.mjs --input security/s2.12-review-input.template.json
```

The evidence reference format is an **opaque internal ticket ID only**,
e.g. `STG-ISOLATION-123`, not a URL with a token, personal identity or
plaintext secret. Store private evidence in an access-controlled
institutional system. Never paste identifiable participant records or
credentials into the Git repository or public PR.

The evaluator checks completeness, SHA binding, a recent S2.10
read-only report (not older than seven days), all 13 manual cases,
CI candidate alignment, PR integration status, four expert-review
tracks, no open Critical/High findings and both security/operations
owners' evidence references. **It does not verify the authenticity of
GitHub run metadata, signatures or claimed evidence files automatically**.
The independent human reviewers must open and validate each source.
A forged all-PASS JSON cannot authorize deployment.

`tests/security-release-decision.mjs` exercises the actual HOLD
template and synthetic nominal/malformed/stale/tampered cases. CI
additionally asserts the current template is **HOLD** to prevent a
passing software test from being described as Production authorization.

## 5. Actions to reach a formal human Go/No-Go meeting

1. **Operator:** present verified isolated Staging origin, empty/synthetic
   database and exact GitHub SHA deployed there. Keep Production GO disabled.
2. **Repository owner:** review/rebase/integrate the unmerged PR stack
   in controlled order and re-run integrated CI at the proposed release SHA.
3. **Security and Staging operator:** configure the protected
   `ACTIVA-Staging-ReadOnly` GitHub Environment with actual Required Reviewers,
   run the read-only S2.10 Staging preflight and capture evidence.
4. **QA:** execute M01–M13 on real Staging/devices using only approved
   synthetic test identities; record PASS/FAIL and remediation tickets.
5. **Security and privacy reviewers:** close Critical/High findings, confirm
   directory policy, CSP, real incident alert delivery, load, logging and
   recovery with independent evidence.
6. **Institutional authority:** review the evidence with the owners.
   Enter a formal signed GO/NO-GO decision in the organization's authorized
   governance records, **not** through this script.
7. **Research team:** maintain a separate ethics/site-authorization
   decision before any empirical human-participant study.
