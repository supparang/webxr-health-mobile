# ACTIVA-AI V0.3.3 — Offline-to-System Prediction Pipeline

## Pipeline
Locked Ground Truth
→ Train / Validation / Final Test
→ Model Evaluation
→ Approval
→ Deployment
→ Export Live Inference Features
→ Offline Prediction + Explanation
→ Batch Import
→ AI/XAI Review
→ Human Final Decision

## Threshold governance
Threshold ถูกกำหนดจาก validation set เท่านั้น
ค่าเริ่มต้นของ prototype คือเลือก threshold ที่ให้ validation F1 สูงสุด โดย tie-break ด้วยค่าที่ใกล้ 0.5

งานวิจัยจริงควรล็อก threshold strategy ใน analysis protocol ก่อนเปิด final test result

## Model artifacts
train_baselines.py สร้าง:
- activa_ai_model.joblib
- evaluation.json
- model_manifest.json
- model_registry_payload.json

model_manifest.json เก็บ:
- model version/family
- features
- calibration method
- locked threshold
- reference values สำหรับ local explanation
- data provenance

## Inference dataset
GET /api/ml/inference-dataset ส่งเฉพาะ feature สำหรับ scoring:
- ไม่มี ground truth
- ไม่มี human decision target
- ใช้ participant_hash แทนรหัสบุคลากร
- ค่าเริ่มต้นไม่ส่ง record ที่มี prediction จาก deployed model แล้ว

## Local XAI
predict_records.py ใช้ single-feature reference perturbation:
- เปลี่ยน feature ทีละตัวกลับเป็น reference value จาก development data
- วัดการเปลี่ยน risk probability
- จัดอันดับ absolute contribution

วิธีนี้เป็น predictive sensitivity explanation ไม่ใช่ causal explanation และไม่ใช่หลักฐานการกระทำผิด

## Import
POST /api/predictions/import-batch:
- รับเฉพาะ deployed model
- probability ต้องอยู่ 0–1
- label ต้องเป็น REVIEW_REQUIRED หรือ NO_REVIEW_REQUIRED
- upsert ตาม attendanceId + modelRunId
- ไม่เปลี่ยน finalEvidenceStatus

Human reviewer ยังคงเป็นผู้ตัดสินใจสุดท้าย
