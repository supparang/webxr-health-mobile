# ACTIVA-AI V1.1.0 Phase 3 — External Blind Reviewer Access

**Protocol extension:** `ACTIVA-P3-RP-001 / P3.2.1`  
**Purpose:** obtain two independent human Ground Truth labels when additional persistent ACTIVA-AI/Google accounts are not available.

## Scientific rule

A pair of links does **not** create two independent reviewers by itself.

Reviewer A and Reviewer B must be two different real people. Each reviewer must attest before submission that they:

- are a real human reviewer;
- reviewed the case independently;
- did not use the other reviewer's link;
- did not consult AI output, rule-consistency output, or the peer label supplied by ACTIVA-AI.

The system records the attestation but does not identity-proof the external reviewer. If a study requires identity-verified reviewers, persistent STAFF accounts or a separately approved identity-verification mechanism must be used.

## Security controls

- 32 cryptographically random bytes per reviewer token.
- Raw token is returned to ADMIN only once.
- Database stores SHA-256 token hash only.
- Link uses URL fragment (`#token=...`), so the token is not sent in the initial HTTP request.
- Browser immediately removes the fragment from the visible URL/history after loading.
- API requests carry the token in `Authorization: BlindReview <token>`.
- API access logging records path/status/duration only; authorization values are not logged.
- Default expiry: 24 hours.
- Allowed expiry: 1–168 hours.
- One successful submission permanently consumes the token.
- Replacing an active batch revokes unsubmitted links from the previous batch.
- Locking Ground Truth revokes any remaining unsubmitted links.
- Voided attendance and already-locked Ground Truth cannot be reviewed.

## Blinding / data minimization

External reviewers receive:

- activity title/category/time window;
- QR validity;
- identity verification flag;
- check-in/check-out presence and times;
- check-out QR validity;
- scheduled/actual duration;
- staff-verification flag;
- signature-verification flag;
- scan-attempt count.

External reviewers do **not** receive:

- participant name;
- employee ID;
- email;
- participant hash;
- AI prediction;
- risk probability;
- XAI explanation;
- rule-consistency result;
- Human Final Decision;
- peer labels.

ADMIN does not receive an external label target through the Ground Truth queue until both reviewers in the batch have submitted.

## P4.6 Internal reviewer authorization clarification

The internal `STAFF` Ground Truth queue now returns only cases from activities where that real account has a current `VERIFIER` assignment. It hides the direct participant identity fields (including name, employee ID, internal user ID and Guest reference); the UI shows a case reference instead. The internal label POST endpoint applies the same activity-assignment check and forbids self-labeling for every role, including ADMIN.

For `EMPIRICAL` activities, ADMIN is the privileged case manager/adjudicator and **cannot directly substitute an ADMIN label** for a separate independent reviewer. Internal labels and external blind submissions are now both checked against the same reason-code set (including mandatory reason codes for `REVIEW_REQUIRED` and notes for `OTHER`). At least two distinct permitted STAFF reviewers and/or the approved external blinded route are necessary. Two different links/tokens establish separate software slots, **not the actual identities of two human reviewers**; the PI must keep an approved private reviewer allocation/independence record outside public GitHub and verify the real-world separation before Ground Truth LOCK is used as scientific evidence. Existing QA_TEST software fixtures remain synthetic, not empirical reviewers.

## Ground Truth resolution

Two available independent labels may be any supported combination of:

- two internal STAFF labels;
- one internal STAFF label + one completed external blind label;
- two completed external blind labels.

Agreement is defined using both target and normalized reason-code set, consistent with the existing Ground Truth resolution policy.

If labels agree, ADMIN may direct-lock by consensus.

If labels disagree, ADMIN must record adjudication notes before locking.

## Audit events

- `EXTERNAL_BLIND_REVIEW_BATCH_CREATED`
- `EXTERNAL_BLIND_REVIEW_SUBMITTED`
- existing `GROUND_TRUTH_ADJUDICATED`
- existing `GROUND_TRUTH_LOCKED`

External submission audit records contain batch/slot/target/attestation metadata and no direct participant identity.

## Operational limitation

The external link is bearer authorization. Anyone who obtains an unused link can act as that reviewer slot. Therefore:

1. ADMIN must deliver A and B links to the intended reviewers through an appropriate channel;
2. links should not be posted publicly or reused;
3. default 24-hour expiry should be retained unless a longer window is operationally necessary;
4. the research record should describe external reviewer independence as **attested**, not identity-verified.

## P3.2 implication

This feature removes the requirement that every independent reviewer hold an ACTIVA-AI account. It does **not** remove the requirement for two different real reviewers or the requirement for empirical LOCKED Ground Truth before sample-plan approval.
