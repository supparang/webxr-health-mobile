## 2. New test/verification contract

- Two actual Ed25519 V2 signatures with synthetic test-approved fingerprints may pass **only** through the synthetic test verifier in a non-Production test runtime.
- An unexpected third argument to `productionReleaseApproval` is ignored, including valid test fingerprints.
- The synthetic verifier rejects when process runtime `NODE_ENV=production`.
- Missing source-enrolled signer fingerprints remain a fail-closed HOLD on the actual Production decision.
- The HTTP service must import/call `productionReleaseApproval` only; no reference to `testOnlyVerifyProductionApproval`.
- Existing S3.7 digest/commit/expiry checks and security regressions remain in place.

**Limitations:** An attacker who can change protected application source, set `NODE_ENV` to bypass bootstrap, or modify the container image has capabilities outside the scope of a JavaScript wrapper. These require independently administered branch protection, build attestations and deployment controls.

## 3. Institutional release-security evidence checklist (not yet verified)

1. **Repository owner / AppSec:** Authenticate branch protection and ruleset screenshots/API export from GitHub repository settings. Protect `main`, release branches and CODEOWNERS changes; require independent reviewer approvals, dismiss stale approvals, reject direct pushes or force pushes, and prevent bypass where supported.
2. **Security authority:** Verify offline that the Security Ed25519 public-key fingerprint belongs to an authorized custodian, with private key not available to deployment operators/CI.
3. **Operations authority:** Independently verify the second fingerprint and that no person/service controls both approval roles.
4. **DevSecOps/build operator:** Attest exact reviewed commit, immutable container artifact digest, Staging-installed artifact and Production target through a protected out-of-band record; investigate any mismatch.
5. **Staging owner / DPO:** Confirm separate Staging origins, test PostgreSQL, secrets, SIEM, network protection, 25 physical/manual test outcomes, evidence retention, incident human acknowledgement and closure of all critical/high findings.
6. **Release authority:** Independently verify full evidence dossier bytes and SHA-256, then obtain two V2 Ed25519 signatures over the final EXACT code revision and evidence. A technical PASS must never self-authorize GO.

**Do not** store real private keys, credentials, identifiable participant records, raw network traces, signed institutional evidence or personal approvals in the repository or public CI artifacts.
