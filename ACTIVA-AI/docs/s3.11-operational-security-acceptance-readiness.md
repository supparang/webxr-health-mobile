## Why this is necessary

The S3.10 inventory accepts well-formed *declarations* about repository rulesets, independent reviewers, source-to-image integrity and isolated Staging. A completed JSON inventory does not verify that GitHub enforces these claimed settings. An administrator with broad privileges might alter source-pinned release verification identities without genuine independent Security/Operations approval.

S3.11 introduces an authenticated **read-only GitHub REST observation** separate from the self-declared inventory. It is not an attestation of reviewer identities, effectiveness of rulesets, or an authorization to deploy.

## Added code

- scripts/probe-github-governance.mjs — fixed HTTPS GitHub API target, GET-only requests for repository, main commit, legacy branch protection, active ruleset list and CODEOWNERS presence.
- tests/github-governance-observation.mjs — synthetic mock tests with no network/real token, including missing permission and no-token failures.
- ACTIVA-AI CI executes only mocked checks; it must NEVER pass real tokens or access live administration APIs.

Observed branches and settings include count of required PR reviews (at least two), dismissal of stale reviews, last-push review, required codeowner reviews, enforced administrator protection, no force-push/deletion, required smoke status, active branch ruleset visibility and CODEOWNERS presence. Each observation may be unverified without sufficient permissions.

## Institutional operator procedure (NOT EXECUTED)

1. On an institution-controlled workstation obtain a short-lived read-only GitHub token with applicable administration metadata access (GitHub documents Administration: read for branch protection). Never paste token into ChatGPT, a repository, a PR, CI or shared evidence.
2. From ACTIVA-AI directory, set ACTIVA_S311_READ_ONLY_CONFIRM=true and ACTIVA_S311_GITHUB_READ_ONLY_TOKEN to the token in a **protected local environment**, then run: node scripts/probe-github-governance.mjs. Remove token from the environment after review.
3. Have two independent security/governance reviewers verify authenticated settings and effective branch ruleset scope, bypass actors and administrators against an independently recorded configuration export.
4. Add actual named independent CODEOWNERS only after separately approving the organizational identities. Do not invent GitHub users or teams.
5. Separately examine approved source SHA, immutable build digest, exact Staging deployment identity, test DB and secret isolation, independent SIEM receipts, human response evidence, 25 manual cases, findings closure and signer custody.

The script performs no POST, PUT, PATCH, DELETE, merge, deploy, user login or real Staging/Production requests. User inputs cannot alter its fixed destination host or repository. Network redirects are rejected. It does not print raw API responses, token, reviewer names, CODEOWNERS contents or errors with arbitrary user-supplied strings.

## Interpretation and safety

- GitHub 403 or 404 does NOT prove that branch protection or CODEOWNERS is missing. It may indicate insufficient permissions; treat as UNVERIFIED.
- Branch protection plus a ruleset list does NOT prove all bypass paths are blocked, that the listed rules match every release branch, or that two independent humans control reviewer privileges.
- CODEOWNERS presence does NOT prove valid syntax, actual required independent owners or codeowner enforcement.
- A runtime commit SHA, registry image digest or human-reviewed evidence reference must be verified from protected external records; this GitHub observation does not attest to deployment.
- All tool outcomes, including every observation satisfied by synthetic mocks, are **decision: HOLD**, mergeApproved false, productionGoApproved false, deploymentApproved false and researchEthicsApproved false.
- GitHub branch rulesets, signer enrollments, 25 real tests, institution-owned Staging/SIEM and independent Security/Operations/Privacy signatures are NOT yet verified by this change.
