## Asset provenance and browser policy

The main ACTIVA-AI UI currently loads:
- QR generator: `https://cdnjs.cloudflare.com/ajax/libs/qrcodejs/1.0.0/qrcode.min.js`
- Camera QR scanner: `https://unpkg.com/html5-qrcode@2.3.8/html5-qrcode.min.js`
- Runtime Google Identity Services JavaScript:
  `https://accounts.google.com/gsi/client` (loaded dynamically in `app.js`)

**SRI scope:** Only the two fixed, version-pinned QR JavaScript files.
The Google Identity Services URL is a service-owned, evolving client script:
pinning a static byte hash to a mutable vendor-served URL is not appropriate
without a stable, reviewed distribution. Instead retain Google's exact-origin
CSP allowlist, OIDC server token validation, and browser acceptance testing.

For each fixed QR file, obtain its **real, exact raw bytes** over TLS,
compute SHA-384, pin the resulting SRI in HTML, and specify
`crossorigin="anonymous"` so cross-origin integrity verification uses CORS.
Before accepting a hash verify the script was downloaded from the exact URL,
that retrieval is not redirected, the size is expected, and browser requests
succeed with CORS. SRI proves a fetched resource matches the approved bytes,
**not** that its code is safe or licensed for a given use.

CI must fail if a third-party script URL is added without reviewed integrity,
if either expected hash changes, or if inline executable JS is introduced.

## Blocking enterprise-level gaps

- `script-src` fixed dependencies are protected only once SRI is verified
  and pinned. Do not invent hash values or approve CDN contents solely by their
  filename/version. Independently inspect library license/provenance and
  scan published bytes, ideally via a review of vendored sources.
- The CSP `connect-src https:` and `style-src 'unsafe-inline'` are still
  broad. Narrow to approved runtime API domains and refactor inline CSS.
- `frame-ancestors` is not enforced by HTML meta on GitHub Pages. Apply
  host/edge response header or migrate sensitive hosted UI to a controlled
  origin where necessary.
- Google OIDC/QR scan tests in CI are not browser-level or human acceptance
  results. Existing CI is synthetic and does not establish real functionality
  for hardware cameras or Google auth popup.
- Authorization, proxy/load-test, distributed security logs/alerts,
  institution-wide directory scoping and independent penetration test are
  separate pre-Production gates.
