# ACTIVA-AI V1.0.0 — Pilot Acceptance Test Scenarios

## A. Identity and access control
### A1 Participant access
Expected:
- Participant cannot access organization analytics, pilot readiness, release gate or backup
- Expected HTTP 403

### A2 Staff access
Expected:
- STAFF can view aggregate analytics, Pilot Readiness and Release Gate
- STAFF cannot export backup, close activity or record GO/HOLD

### A3 Admin release authority
Expected:
- ADMIN can perform closure, backup/recovery check and release decision
- Every irreversible/release action creates AuditLog evidence

## B. Human Review integrity
### B1 Final authority
Expected:
- AI prediction never changes finalEvidenceStatus
- Human Review remains required for final operational decision

### B2 Rationale
Expected:
- Every Human Decision requires an explicit reason
- Manual Override keeps the stronger reason requirement

## C. Immutable activity closure
### C1 Closure gate
Prepare an ended activity.
Expected:
- Cannot close when Evidence Evaluation is incomplete
- Cannot close when unresolved review exists
- Cannot close with critical data-quality issue

### C2 Successful closure
Expected:
- pilotClosedAt recorded
- release version recorded
- closure snapshot recorded
- closure hash recorded
- Audit action ACTIVITY_PILOT_CLOSED recorded

### C3 Mutation lock
After successful closure, attempt:
- participant change
- assignment change
- QR issuance
- check-in/out
- staff verify
- void
- Evidence re-evaluation
- Human Review

Expected:
HTTP 423 ACTIVITY_PILOT_CLOSED_IMMUTABLE

## D. Backup and recovery
### D1 Export
Expected:
- ADMIN can export
- Backup declares containsPII=true
- Backup declares containsSecrets=false
- QR cryptographic credentials are excluded
- checksum present

### D2 Valid recovery check
Upload the exported backup unchanged.
Expected:
- restorableStructureVerified=true
- destructiveRestorePerformed=false
- currentReleaseVersionMatch=true
- Audit action BACKUP_RECOVERY_CHECK_PASSED

### D3 Tamper detection
Modify one payload item without changing checksum.
Expected:
HTTP 422 BACKUP_CHECKSUM_MISMATCH

## E. Release gate
### E1 Security placeholders
If production secrets still use placeholders:
Expected:
HOLD with SECURITY_CONFIGURATION_NOT_PRODUCTION_READY

### E2 Unclosed ended activity
Expected:
HOLD with ENDED_ACTIVITIES_NOT_IMMUTABLY_CLOSED

### E3 Backup/recovery missing
Expected:
HOLD with RECENT_BACKUP_RECOVERY_CHECK_REQUIRED

### E4 GO candidate
Prerequisites:
- production secrets configured
- no critical data-quality issue
- no over-target review backlog
- every ended activity immutable-closed
- current-release backup recovery-check passed within 24 hours

Expected:
gate=GO

### E5 Release decision
ADMIN records reason and GO/HOLD.
Expected:
- audit action PILOT_RELEASE_GO or PILOT_RELEASE_HOLD
- AI cannot trigger this endpoint autonomously

## F. Demo safety
Expected:
- Demo data remains synthetic
- Demo release gate always HOLD
- Demo GO attempt is rejected
