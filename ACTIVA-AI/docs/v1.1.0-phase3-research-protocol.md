# ACTIVA-AI V1.1.0 Phase 3 — AI/XAI Research Validation Protocol

**Protocol ID:** `ACTIVA-P3-RP-001`  
**Status:** IMPLEMENTATION BASELINE — sample-size plan pending approval  
**Phase 2 baseline:** `release/activa-ai-1.0.16-phase2-complete` at commit `acf438dfb1671fe5030aa75f011dfc8925a96d55`  
**Core rule:** AI is decision support only. Human Final Decision remains authoritative.

## 1. Phase 3 purpose

Phase 3 evaluates whether ACTIVA-AI can use de-identified, LOCKED empirical ground truth to prioritize records for Human Review while preserving the governance separation already established in Phase 2.

Phase 3 does **not** authorize autonomous personnel decisions and does not reopen Phase 2 acceptance evidence.

## 2. Primary research question

Can a supervised risk model trained only from protocol-eligible evidence available before Human Final Decision discriminate records that require review from records that do not require review, with acceptable calibration and without participant or target leakage?

Target:

- `REVIEW_REQUIRED` = positive class
- `NO_REVIEW_REQUIRED` = negative class

The target comes only from adjudicated and LOCKED Ground Truth.

## 3. Prediction moment

The prediction moment is frozen as:

`AFTER_EVIDENCE_COLLECTION_BEFORE_HUMAN_FINAL_DECISION`

Only variables available at that moment are eligible as model predictors.

Human-review outcome, final decision, adjudication rationale, locked target metadata, AI predictions from another model, names, emails, employee IDs, and other direct identifiers are excluded from predictors.

## 4. Dataset provenance gate

Empirical Phase 3 training data must come from:

`GET /api/ml/dataset`

Required dataset contract:

- `datasetStatus = LOCKED_GROUND_TRUTH_ONLY`
- `deidentified = true`
- `aiPredictionsIncluded = false`
- Demo/synthetic datasets are prohibited as research evidence
- all records have a valid `final_target`
- `record_id` values are unique
- `participant_hash` is used for grouping; direct identity fields are prohibited

Before training, complete and approve `ml/phase3-sample-plan.json`, then run:

`npm run phase3:dataset-check -- --input <locked_dataset.json> --sample-plan ml/phase3-sample-plan.json`

Directly supplying numeric thresholds without an APPROVED sample plan can be used for structural diagnostics, but it cannot set `researchTrainingAuthorized=true`.

The structural validator does not replace formal sample-size/power planning.

## 5. Frozen baseline feature set

Numeric/binary evidence features:

- `qr_valid`
- `identity_verified`
- `checkin_present`
- `checkout_present`
- `scheduled_duration_minutes`
- `actual_duration_minutes`
- `duration_ratio`
- `checkin_offset_minutes`
- `checkout_offset_minutes`
- `staff_verified`
- `signature_verified`
- `scan_attempts`

Categorical feature:

- `activity_type`

Grouping fields, not predictors:

- `participant_hash`
- `event_id`

Research/audit fields, never predictors:

- `record_id`
- `final_target`
- `reason_codes`
- `locked_at`

Any feature-set change after real-data inspection requires a protocol amendment before final-test evaluation.

## 6. Split strategy and leakage prevention

Primary split is group-aware by `participant_hash` so the same participant does not appear across train/validation/test partitions.

Pre-specified sensitivity analysis may use `event_id` grouping to evaluate cross-activity generalization.

The final test partition must remain untouched during:

- model-family selection;
- feature selection;
- calibration selection;
- threshold selection;
- hyperparameter tuning.

## 7. Candidate models

The existing Phase 3 baseline pipeline compares:

- Logistic Regression
- Random Forest
- Gradient Boosting

No model family is designated the winner in advance.

Model-family selection uses validation PR-AUC only. The selected threshold is locked from validation data only.

## 8. Evaluation outcomes

Required predictive metrics:

- Precision
- Recall / Sensitivity
- Specificity
- F1
- ROC-AUC
- PR-AUC
- Brier Score
- Calibration curve
- cluster-bootstrap 95% confidence intervals

Required operational/Human-AI outcomes for the shadow pilot:

- review workload volume;
- review prioritization yield;
- false-positive and false-negative counts;
- AI ↔ Ground Truth agreement;
- AI ↔ Human Final Decision agreement;
- Evidence Engine ↔ Human Final Decision agreement;
- median review duration;
- human override/disagreement rate.

Predictive explanation is not causal explanation.

## 9. XAI

Baseline global explanation uses permutation importance.

Local explanations may be generated for shadow/decision-support predictions after a model is approved. Explanations must be labelled predictive and must never be presented as proof of cause or misconduct.

## 10. Model governance

Required state path:

`CANDIDATE → EVALUATED → APPROVED → DEPLOYED → RETIRED`

A model may not enter DEPLOYED state unless:

1. provenance is empirical LOCKED Ground Truth;
2. dataset contract passes;
3. the pre-specified sample plan is approved;
4. evaluation report is complete;
5. threshold is locked from validation data;
6. final-test metrics are retained without post-test retuning;
7. Human Final Decision remains authoritative.

Synthetic CI models remain software-test artifacts only.

## 11. Sample-size gate

No arbitrary scientific minimum is hard-coded in this protocol.

Before empirical model training, record an approved sample plan containing at least:

- anticipated prevalence of `REVIEW_REQUIRED`;
- minimum total records;
- minimum unique participants;
- minimum activities/events;
- minimum positive and negative target counts;
- rationale for the planned model complexity and validation strategy.

These approved values are stored in the version-controlled `ml/phase3-sample-plan.json`. The validator reads that plan and authorizes empirical training only when the plan status is `APPROVED` and all minimums are positive integers.

**Current sample-plan status: PENDING.**

Until this becomes APPROVED, empirical training is **HOLD** even if structural validation passes.

## 12. Phase 3 implementation gates

### P3.0 — Baseline freeze
PASS when the Phase 2 completion commit is preserved on the release baseline branch.

### P3.1 — Research protocol and dataset contract
PASS when protocol, feature contract, dataset validator, and CI regression tests are merged.

### P3.2 — Empirical dataset readiness
PASS when the approved sample plan exists and the locked empirical export passes the validator.

### P3.3 — Offline model evaluation
PASS when the pre-specified pipeline produces retained model/evaluation/manifest artifacts.

### P3.4 — Human approval gate
PASS only after a human research/operator review approves the evaluated model for shadow use.

### P3.5 — Shadow decision-support pilot
AI risk/XAI may prioritize the queue but may not change Final Human Decision.

### P3.6 — Phase 3 research evidence lock
Freeze the dataset snapshot, code commit, model manifest, threshold, final evaluation, and shadow-pilot evidence used for publication.

## 13. Stop conditions

Place Phase 3 on HOLD if:

- direct identifiers enter the ML dataset;
- synthetic/demo data are mixed with empirical research data;
- Ground Truth is not LOCKED;
- prediction or Human Final Decision fields leak into predictors;
- participant groups overlap train and test;
- the final test set is used for tuning;
- the model changes a personnel decision autonomously;
- provenance of a reported metric cannot be reconstructed.
