## Known remaining risks — blocking any Production release

1. **Institutional role scoping:** independent review of activity assignments,
   role revocation, multi-activity staff privileges, and `CAN_MANAGE_ALL_ACTIVITIES`
   semantics. Non-admin personnel directory remains wide (minimal fields)
   pending a least-privilege product decision. **SEC-04 partial.**
2. **Rate limiting:** counter data are per Node process. A real Render/ingress
   proxy may collapse client IPs; no accepted multi-instance/distributed rate
   limiting or representative peak classroom load test exists.
3. **Security alerting:** aggregate counters reset on process restart. GitHub
   delivery uses an in-memory queue and is **DISABLED** by default. A successful
   2xx from GitHub does not prove a human acknowledged the incident. Provider
   log forwarding, on-call backup and live Staging delivery are not accepted.
4. **Privacy/governance:** retention on Render/GitHub, redaction in external
   proxy logs, operator access and breach-response runbook need verification.
5. **UI/Frontend and CSP:** XSS, HTML rendering, dependency security and an
   enforced Content Security Policy remain for subsequent security work.
6. **Research Phase 4:** the project must stay on ethics/site-authorization
   HOLD independently of Software Production Security acceptance.
