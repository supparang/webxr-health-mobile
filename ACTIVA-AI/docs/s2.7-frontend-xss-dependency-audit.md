# ACTIVA-AI S2.7 — XSS Sinks and External-Dependency Security Audit

**Status:** DRAFT, stacked on unmerged S2.6 PR #141; no Production deployment or real-person data.
**Security goal:** Reduce attacker-controlled strings reaching HTML/attribute contexts, and verify browser script + npm dependency sources are pinned and reviewed.
This is a focused hardening pass, **not** a complete proof that every dynamic HTML template is safe.

## Findings and remediation (14 October 2026)

| ID | Finding | Priority | Change |
| --- | --- | --- | --- |
| XSS-01 | Ground Truth reason codes were inserted directly into a checkbox `value` attribute and text from a collection assembled using stored label data (`app.js` Ground Truth renderer). Malformed codes could break attribute/text context and inject markup if untrusted data reaches this array. | HIGH | `esc(code)` in **both** attribute and text; a synthetic malicious-value test executes the **actual** reason code expression. |
| XSS-02 | User and model identifiers, record IDs and activity IDs were interpolated directly into `data-id` or `option value` HTML attributes. These are normally server-assigned, but escaping still needs to hold if invalid or imported values reach UI. | MEDIUM | Escape user/model/attendance/activity identifiers and dynamic status attributes at HTML insertion. |
| XSS-03 | Navigation labels, form helper IDs/type, role options, activity count, filter labels, assignment data-* values had inconsistent escaping. Most are server-controlled or static, but safe HTML output must not rely on their present origin. | MEDIUM | Escape at the destination for dynamic text/attributes. |
| DEP-01 | Two third-party QR libraries are loaded from explicit versions on public CDNs; **neither external script has an SRI integrity attribute**. A compromised or changed CDN response remains an outstanding supply-chain risk. | HIGH (release gate) | Add test that external script URLs remain restricted to two exact versioned paths. **Not a substitute for cryptographic integrity.** Before Production release, vendor audited byte-pinned copies or independently obtain, verify and include actual SRI hashes. |
| DEP-02 | Production Node packages are installed using npm package-lock plus `npm ci` and `npm audit --audit-level=high` on CI. Vulnerability status can change between runs. | VERIFY | Enforce registry entry `integrity` fields for all locked packages, retain recurring updates/security review, and re-run latest audit before go/no-go. |

## Automated coverage

`tests/frontend-xss-dependencies.mjs`:
- Loads **actual** escape helper and HTML field/check helpers isolated in Node `vm`, submits a malicious HTML text/attribute value, asserts escaped output.
- Loads actual Ground Truth reason-code renderer expression; asserts injected `<img>`, `<svg>` and attribute breakouts are not rendered unescaped.
- Guards critical record/user/model/permission IDs and status attribute escaping.
- Asserts no `document.write`, dynamic `eval/Function`, or string-based interval API is introduced in `app.js`, `guest.js`, `blind-review.js`.
- Requires Guest consent/activity and Blind Review case/activity text to remain escaped.
- Fails on new/unversioned remote scripts in `index.html`; requires integrity fields on locked npm-registry dependency entries.

CI executes the new test before the standard authentication / smoke / full application suite.

## Known limitations and required further verification

1. **SRI/vendoring not complete.** No externally obtained script digest is included because it was not verified. Versioned CDN addresses and CSP allowlists restrict loading locations, but cannot cryptographically prove the bytes. Never invent a hash or relax `script-src`.
2. **Full DOM sink analysis not finished.** `app.js` is large and generates significant HTML strings using `innerHTML` and `insertAdjacentHTML`. Static checks catch the cited classes; they do not model every branch, URL/style/DOM clobbering or every remote data source. Browser-level DOM XSS tests and independent penetration assessment remain mandatory.
3. **Runtime CSP compatibility not confirmed.** Verify Google Sign-In popup and `Html5Qrcode` camera under real Staging with DevTools console/Network open; adjust only narrowly scoped directives based on actual violations.
4. **API/directory data scope from S2.1** is still partially open; S2.7 escaping alone does not authorize exposing an entire personnel directory.
5. **CDN and npm supply chain:** evaluate moving QR scripts to reviewed local assets with license/provenance inventory and SHA-384 checksums. Do not rely on an unreviewed package `latest` update.
6. **Security notification delivery and load tests** remain HOLD until a named responder receives actual Staging alerts and network topology is approved.
